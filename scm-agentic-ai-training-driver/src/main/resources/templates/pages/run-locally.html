Hands-On Setup Guide

Run the Complete SCM Agentic AI POC on Your Laptop

This guide walks through the complete local setup of the End-to-End Supply Chain Agentic AI Proof of Concept on either macOS or Windows.

You will install the required development tools, clone the GitHub repository, install and configure Keycloak 26 for SSO, create the MySQL schemas and seed data, build and run seven independent Spring Boot REST APIs, launch the Spring Boot ERP dashboard, and finally configure and start the Python / LangGraph Agent Control Tower.

Realm Configuration

Import the scm-poc Realm

The repository ships a ready-made Keycloak realm export file (scm-poc-realm.json) that creates all clients, roles, and test users in a single import. Do not create the realm manually — use the file.

Type Name Purpose
Realm scm-poc Top-level security realm for the entire POC
Client scm-python-chatbot Public PKCE client — Python chatbot browser login
Client scm-service-client Confidential M2M client — Python chatbot → REST APIs
Client scm-ui-dashboard Confidential client — Thymeleaf dashboard login
Client cs-crm-api … cs-tms-api 7 resource server clients (one per REST API)
Role scm_admin Full read/write access to all services
Role scm_manager Read all + write (POST/PUT/PATCH) to all services
Role scm_viewer Read-only (GET) access to all services
User scm.admin / Admin@2025! Test user — all three roles
User scm.manager / Manager@2025! Test user — scm_manager + scm_viewer
User scm.viewer / Viewer@2025! Test user — scm_viewer only
1

Locate the Realm File in the Repository

After cloning the repository, the realm file is at:

└── keycloak/
    └── scm-poc-realm.json
2

Open the Keycloak Admin Console

Browser 
http://localhost:8080/admin

Log in with the admin credentials you created during the first-time Keycloak setup.

3

Import the Realm JSON

  1. In the top-left corner click the realm dropdown (currently showing master)
  2. Click Create realm
  3. Click Browse next to Realm file
  4. Select scm-poc-realm.json from the repository's keycloak/ folder
  5. Click Create
Always use the JSON file — never create the realm manually

The realm JSON pre-configures all eleven built-in client scopes (openid, profile, email, roles, web-origins, acr, basic, etc.) with their protocol mappers. Creating the realm through the UI without the JSON will result in missing scopes and broken token claims.

5

Smoke-Test the Token Endpoint

Run this command to confirm Keycloak is issuing valid JWT tokens with the expected roles claim.

Terminal 
# Request a token using the password grant (test only)
curl -s -X POST \
  "http://localhost:8080/realms/scm-poc/protocol/openid-connect/token" \
  -d "grant_type=password" \
  -d "client_id=scm-python-chatbot" \
  -d "username=scm.admin" \
  -d "password=<your-password>" \
  -d "scope=openid profile email" | python3 -c "
import sys, base64, json
resp = json.load(sys.stdin)
t = resp['access_token'].split('.')[1]
p = t + '=' * (4 - len(t) % 4)
decoded = json.loads(base64.urlsafe_b64decode(p))
print(json.dumps({
  'username': decoded.get('preferred_username'),
  'roles':    decoded.get('realm_access', {}).get('roles', [])
}, indent=2))
"

A successful response shows scm.admin as the username and all three roles in the realm_access.roles array.

Enable Direct Access Grants for smoke testing

The password grant above requires Direct Access Grants to be enabled on the scm-python-chatbot client. In the Admin Console: Clients → scm-python-chatbot → Settings → Capability config → Direct access grants → ON. This setting is for local testing only and can be turned off in a real deployment.

Build

09
Runtime

Start the Spring Boot Services

Java 
java -jar target/<file-name>.jar
JWT validation starts automatically

Each Spring Boot service validates incoming Bearer tokens against Keycloak's JWKS endpoint (http://localhost:8080/realms/scm-poc/protocol/openid-connect/certs). Keycloak must be running before the APIs start. All endpoints return 401 Unauthorized without a valid token; /actuator/health remains open.

Multiple applications require multiple terminals

Keep each Spring Boot service running in its own terminal tab/window, or run them directly through separate IntelliJ run configurations.

Quick security check — confirm all APIs reject unauthenticated requests

Run this one-liner to confirm all seven REST APIs return 401 without a token and 200 with a valid Keycloak JWT:

Terminal — Security Smoke Test 
# Step 1 — confirm all APIs reject requests without a token (all should return 401)
for port in 8081 8082 8083 8084 8085 8086 8087; do
  code=$(curl -s -o /dev/null -w "%{http_code}" http://localhost:$port/api/v1/)
  echo "Port $port: $code"
done

# Step 2 — get a token and confirm all APIs accept it (all should return 200)
curl -s -X POST \
  "http://localhost:8080/realms/scm-poc/protocol/openid-connect/token" \
  -d "grant_type=password" \
  -d "client_id=scm-python-chatbot" \
  -d "username=scm.admin" \
  -d "password=<password>" \
  -d "scope=openid profile email" | python3 -c "
import sys, json, subprocess
token = json.load(sys.stdin)['access_token']
for port, path in [(8081,'/api/v1/campaigns'),(8082,'/api/v1/rfqs'),
                   (8083,'/api/v1/purchase-orders'),(8084,'/api/v1/asns'),
                   (8085,'/api/v1/store-orders'),(8086,'/api/v1/shipments'),
                   (8087,'/api/v1/delivery-loads')]:
    r = subprocess.run(['curl','-s','-o','/dev/null','-w','%{http_code}',
        '-H',f'Authorization: Bearer {token}',
        f'http://localhost:{port}{path}'],capture_output=True,text=True)
    print(f'Port {port}: {r.stdout}')
"
