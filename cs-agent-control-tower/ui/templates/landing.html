01 — WHY THIS EXISTS
Business Purpose

A single supply chain run normally means one person clicking through seven different systems in the right order and hoping nothing was missed. This agent does that sequencing itself, and only interrupts a human when the decision is actually worth interrupting for.

Autonomous Orchestration

Given one plain-English goal, Claude decomposes it into an ordered sequence of skill calls across CRM, Vendor, Procurement, WMS, OMS, and TMS — and executes that plan step by step, adapting as each result comes back.

Human-in-the-Loop Governance

High-value or irreversible actions — awarding a vendor contract, approving a purchase order — pause the run and wait for explicit human approval, rejection, or override before proceeding.

Full Cost & Audit Trail

Every Claude call and every downstream API call is logged with full request/response, token counts, and USD cost — broken down per user, per day, and per month for Security and Finance to review directly.

02 — HOW IT'S BUILT
Architecture

A Python/Flask agent sits between Claude and seven independent Spring Boot microservices, with an event bus, a human-approval gate, and a full observability layer wrapped around every call it makes.

Claude (Planner) Agent Orchestrator Skill Modules 7 SCM Services RabbitMQ Events
Reasoning Layer

Claude plans the step sequence, scores confidence per action, narrates the finished run in plain English, and scans for anomalies across recent results.

reasoning/planner.py · reasoning/narrator.py
Orchestration Layer

A plain-Python execution loop runs the plan step by step, streaming log lines to the UI over SSE as each skill completes.

orchestrator/graph.py · orchestrator/state.py
Skills Layer

Eight self-contained modules, one per business capability, each wrapping the relevant downstream service calls behind a single typed entry point.

skills/*.py
Governance Layer

Approval gates block execution on high-value steps until a human approves, rejects, or overrides — the run simply waits, it doesn't guess.

hitl/gate.py · hitl/approval_routes.py
Security Layer

Keycloak SSO gates every user, while a separate service-account client authenticates the agent's own calls to the seven downstream APIs.

auth/oidc.py · api_clients/keycloak_auth.py
Observability Layer

Every LLM call and HTTP call is logged to JSONL and SQLite with full request/response and cost, plus Prometheus metrics for scraping.

observability/*.py · /audit · /metrics
