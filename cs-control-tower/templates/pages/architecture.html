System Architecture — Connected Enterprise

How the 8-service ecosystem is designed, why each component exists, and how events flow end-to-end.

Big Picture
What we are building

Burger Bliss is running its SUMMER25-TOY campaign — placing mystery toy figures inside kids meals across 3,200 US restaurant locations. This simulation models the full enterprise supply chain from marketing campaign launch to physical proof-of-delivery at every store, orchestrated across 8 microservices communicating via RabbitMQ domain events.

The Flask Control Tower is the AI brain on top: it listens to all events, maintains a BI read-model, and lets any stakeholder ask questions in plain English — from the CEO asking "how many toys have reached our restaurants?" to an operations manager asking "which loads are still in transit?".

RabbitMQ Event Chain

All services publish to erp.topic.exchange (durable, topic type). Routing keys follow the pattern erp.{service}.{entity}.{action}. The Control Tower subscribes to erp.# (wildcard) to capture every event.

AI Two-Pass NL Pipeline

When a stakeholder asks a question, the Control Tower runs two Claude API calls:

Pass 1 — Parse
User's English question is sent to Claude with a system prompt that describes all 7 service API endpoints. Claude responds with a JSON object specifying the service, method, path, and optional payload. 
{
  "service": "tms",
  "method": "GET",
  "path": "/api/v1/delivery-loads/status/COMPLETED",
  "intent_summary": "fetch completed delivery loads"
}
↓ Flask calls the Spring Boot API ↓
Pass 2 — Narrate
The raw JSON API response is sent back to Claude with the original question. Claude synthesises a friendly, business-focused English answer, highlighting key numbers, statuses and anomalies.
"Two delivery loads for SUMMER25-TOY are COMPLETED. LOAD-2025-001 delivered 128,000 Dino toys to 4 Midwest stores via XPO, and LOAD-2025-002 delivered 104,000 units to 4 Southeast stores via Old Dominion. All stores have confirmed POD."
BI Database Design

The Control Tower maintains its own SQLite read-model, populated by the RabbitMQ subscriber. This enables fast analytics without hitting the operational databases.

TablePurpose
erp_eventsAppend-only log of every RabbitMQ message received
campaign_summariesDenormalised rollup per campaign code, updated per event
delivery_trackingPer-region delivery status from TMS pod-confirmed events
chat_historyEvery AI chat interaction stored for audit and replay
